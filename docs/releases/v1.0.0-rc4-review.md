# ContextOS v1.0.0-rc4 security and release review

Review scope: RC4 source changes, provider adapters, routing, API/CLI surfaces,
telemetry, and release configuration.

| Area | Result | Evidence |
|---|---|---|
| API key leakage | PASS | Keys are read only from named environment variables at dispatch time; values and authorization headers are never logged, returned, or persisted. |
| Remote consent | PASS | Remote dispatch and fallback require `allow_remote`; CLI and API default to false. Explicit provider selection is visible in the request. |
| Cloud fallback | PASS | Local-first fallback requires both fallback and remote consent; unavailable or uncredentialed remote providers are excluded. |
| Telemetry privacy | PASS | Telemetry stores provider/model/status and bounded usage only; prompt, response, keys, URLs, and headers are excluded. |
| SSRF and base URLs | PASS | URLs are constrained to HTTP(S), credentials/query/fragment are rejected, redirects and proxy environment settings are disabled, and non-loopback plain HTTP is rejected. |
| Error sanitization | PASS | Provider errors expose typed, bounded messages and status classes; raw response bodies, headers, URLs, and secrets are not propagated. |
| Malformed provider responses | PASS | Native and compatible adapters validate response shape, text blocks, IDs, and usage fields; malformed payloads fail with typed errors. |

Findings: Critical 0, High 0, Medium 0.

Static validation: targeted Ruff and strict Mypy pass for the RC4 provider,
configuration, routing, wiring, and model-route changes. Existing repository
diagnostics outside the RC4 delta are unchanged and are not release blockers.
