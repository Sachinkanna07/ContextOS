# ContextOS v1.0.0-rc2 Release Notes

**Release Date:** October 3, 2026  
**Artifact Version:** `1.0.0rc2`

---

## What ContextOS Is

ContextOS is a local-first, model-independent AI memory runtime. It is designed to sit between user activity and AI models, providing privacy-scanned persistent memory, temporal state resolution, hybrid RAG retrieval, token-aware context optimization, and context compilation.

ContextOS is not a chatbot framework or cloud service; it operates entirely locally on standard Python runtimes with a daemon architecture, terminal tools, MCP interface, and explicit connectors.

---

## Major Features

1. **Persistent Local Memory & Lifecycle:** SQLite storage (Schema v7) with append-only event logging, status transitions (`ACTIVE`, `SUPERSEDED`, `HISTORICAL`, `PURGED`), and versioned memory records.
2. **Privacy Boundary & Secret Scanning:** Local pattern-based secret detection applies the configured reject/quarantine/redact policy to supported credential shapes on write paths. It does not universally detect or redact private filesystem paths. Selected graph/provenance outputs suppress path-shaped labels; terminal sanitization removes control sequences.
3. **Temporal Memory Engine:** Slot-key relation resolution handling supersession, contradiction, and coexistence without dropping historical context.
4. **Hybrid RAG & Index Synchronization:** Dual lexical (BM25) and dense vector indexing combined using Reciprocal Rank Fusion (RRF) with batched candidate hydration.
5. **Token-Aware Context Optimizer & Compiler:** Knapsack optimization for context selection under model token budgets with evidence and fact-formatting provenance.
6. **Bounded Memory Graph:** Deterministic entity/relation projection with dirty-bit caching and opt-in graph traversal.
7. **Model Router & Telemetry:** Provider-agnostic dispatch with per-model token accounting and provenanced tokenizer tracking.
8. **Model Context Protocol (MCP):** STDIO server (`contextos-mcp`) providing tools with explicit permission boundaries.
9. **File & JSONL Connectors:** High-performance local file and structured JSONL importers with incremental sync skipping unchanged items.
10. **Terminal Dashboard & Inspector:** Interactive monitor (`contextos monitor`, `stats`, `desktop`), local inspector (`contextos inspect`, using the running daemon), and diagnostic health check (`contextos doctor`).
11. **Decoupled Packaging:** Core defaults use hashed deterministic embeddings and `APPROXIMATED` word-token accounting without model/tokenizer downloads. This is an offline baseline, not a SentenceTransformer-quality claim. PyTorch-based embeddings are optional (`pip install "contextos-memory-runtime[embeddings]"`) and must be explicitly configured. Archive sizes exclude installed dependencies; exact rebuilt sizes are reported by `python tools/validate_release_artifacts.py`.

## Installation & Quick Start

Measured rebuilt archives are approximately **220 KB (wheel)** and **300 KB (sdist)** in decimal units. Installed dependency footprint is separate. `python tools/validate_release_artifacts.py` reports exact byte counts for the current artifacts.

### Core Installation
```powershell
pip install contextos-memory-runtime
```

### With Local Embedding Extra
```powershell
pip install "contextos-memory-runtime[embeddings]"
```

The extra does not change defaults. Explicitly configure `[embedding]` with `model = "all-MiniLM-L6-v2"` to select SentenceTransformer embeddings; first use may download that model unless provisioned locally. Core `model = "deterministic"` needs no model assets.

Token accounting defaults to `[token_counter]` with `encoding = "deterministic"`. Exact counting is opt-in via `encoding = "cl100k_base"` or `"o200k_base"`; provision the corresponding tokenizer cache before offline use. The demo explicitly selects the approximate counter even when the runtime configuration requests exact counting.

### Development Installation
```powershell
pip install -e ".[dev]"
```

### Quick Start & Offline Demo
```powershell
# Run the self-contained offline walkthrough
contextos demo

# Start the background daemon and check system health
contextos start
contextos doctor
contextos stats

# Ingest memory & inspect retrieval decision pipeline
"I prefer concise technical explanations." | contextos memories remember
contextos inspect "What explanation style do I prefer?"

# Stop daemon
contextos stop
```

## Benchmark Scope & Evidence Summary

The canonical benchmark suite (`python -m contextos.benchmarks.final`) evaluates ContextOS on 100 and 1,000 synthetic memory datasets across five retrieval strategies:

- **Full History:** Complete context without filtering
- **Vector RAG:** Dense embedding similarity search
- **Hybrid RAG:** Combined BM25 + Vector retrieval
- **Hybrid + Graph:** Hybrid retrieval augmented with graph traversal
- **ContextOS Pipeline:** Complete hybrid retrieval, temporal filtering, knapsack optimization, and context compilation

The canonical benchmark explicitly retains `cl100k_base` counting, requiring a provisioned tokenizer cache or first-use asset download. Its exact synthetic counts are separate from the core demo approximations and do not establish provider-billed savings.

### Measured Benchmark Highlights (1,000 Memories):
- **Recall@5:** Vector ~0.60, Hybrid ~0.90, Hybrid+Graph ~0.50, ContextOS ~0.85
- **Weighted Token Reduction:** 69.59% (100 memories) / 77.46% (1,000 memories)
- **ContextOS Latency:** ~198 ms mean pipeline latency in the latest independent run

## Known Limitations

1. **Answer Quality Not Validated:** Benchmark evaluations grade retrieval precision, context token reduction, and temporal correctness. Generated LLM answer correctness is not evaluated or claimed.
2. **Graph Retrieval Is Opt-In:** The latest independent synthetic run measured graph-assisted retrieval at ~456 ms versus hybrid ~191 ms, with Recall@5 0.50 versus 0.90 at 1,000 memories. These local measurements do not establish universal graph quality. Graph retrieval remains opt-in.
3. **Live External Providers Not Validated:** Tests and benchmarks run against local deterministic providers (`DeterministicEmbedding`, `FakeProvider`). Live remote provider APIs (OpenAI, Anthropic, Ollama) require explicit user setup and network access.
4. **CLI Cold Startup Latency:** The latest independent Windows audit measured five fresh CLI processes at ~2.273 seconds median (~2.362 seconds maximum). This is a local measurement, not a performance guarantee.
5. **Python Version Validation:** Python 3.12 is supported by declaration in `pyproject.toml`, but full verification for this release candidate was performed on Python 3.13.5 (Windows 11).

## RC2 changes

The distribution name changes to `contextos-memory-runtime`; the ContextOS brand, `contextos` import and CLI, and `contextos-mcp` remain. Background startup waits up to 30 seconds for readiness (configurable, minimum 20s bound), with short polling intervals, and terminates failed children. Existing-daemon readiness requires a positive recorded PID, a live verified ContextOS process, an exact endpoint PID match, and verified OS TCP listener ownership on the configured host/port via connection inspection. Startup and stop hold a Windows/POSIX OS lifecycle lock with a 45-second acquisition timeout (minimum 30s bound). Concurrent starters wait and report the verified surviving daemon as already running. Daemon ownership and lifecycle state survive starter-process death: the daemon independently registers durable identity before binding, enforcing the invariant that readiness implies recoverable registration. The starter atomically publishes ready daemon state (including Windows venv launcher children), and compare-before-delete cleanup removes only matching owned state. The lock file remains in place; OS ownership releases on process exit, including crashes.
