# Performance evidence

Measurements are local synthetic runs on Windows 11 / Python 3.13.5, not SLA guarantees. For the earlier 1,000-memory, four-query, two-iteration profiling corpus, candidate hydration formerly made one SQLite `get()` call per index candidate. The bounded `get_many()` path now reads at most 400 IDs per query batch, preserving the generic repository fallback. Hybrid strategy mean in two separate runs changed from 698.121 ms to 173.047 ms (525.074 ms, about 75.2% lower). The same-run environment was used, but scheduler/tie variance means the percentage should not be generalized. At 100 records, hybrid mean changed from 75.549 ms to 19.589 ms.

Temporal peer profiling on 600 active synthetic records and 25 decisions showed the prior 500-row scan at 37.549 ms mean; SQL latest-peer lookup measured 3.696 ms initially and 2.704 ms in the latest run (separate runs varied). The SQL query plan used `idx_memories_status` and a temporary order-by B-tree, so a subject/property expression index may be useful if future real-world profiling justifies a migration. The new lookup also repairs a correctness issue when the relevant peer lies beyond the former 500-row scan.

The latest reproduced ten-query final run measured 435.317 ms mean for opt-in hybrid+graph at 1,000 records, versus 196.635 ms for hybrid (an earlier run measured 324.288/152.019 ms). The graph path now applies the remaining edge budget in its SQLite neighbor query to bound high-degree hydration; this is a resource bound, not a speedup claim. Index freshness checks still load the indexable corpus; the in-memory BM25/dense search and graph traversal are corpus-dependent. These are remaining scale costs, not hidden by the CLI. No connector or cold-start optimization is claimed without paired measurements. See the canonical connector/terminal/explainability benchmark outputs for their own measured scopes.

The existing terminal harness separately measured five-process CLI startup at 1,593.431 ms median (1,635.328 ms maximum). `python -X importtime -m contextos --help` showed roughly 1.34 s cumulative import time for `contextos.cli.app` and substantial Typer/Rich import cost; no cold-start rewrite was made. Dashboard refresh median was 10.676 ms with a 2,051.495 ms maximum in the five-sample run, reflecting an expensive cold discovery sample. The connector harness measured 100 initial accepts in 1,487.71 ms versus 100 unchanged items skipped in 34.02 ms; 1,000 initial accepts took 17,875.45 ms and unchanged repeat 316.67 ms. These are independent harnesses, not before/after connector optimization claims.
