# Security and failure boundaries

The daemon is intended for a trusted local user on loopback, not untrusted multi-tenant access. The privacy scanner is applied before extraction and temporal persistence on CLI/API/MCP/connector writes. Connector source bodies, credential values, raw prompts, and raw provider responses must not enter connector cursor state or invocation telemetry. Explicit content viewing can disclose private data on the terminal; the default dashboard, graph, history, inspection, and status paths are metadata-oriented.

New adversarial tests cover hostile stored terminal text in inspector/graph output, oversized inspection input with no echoed payload, and a credential-shaped graph entity label/project scope. The last case reproduced a leak and is now rejected by graph path label sanitization. The test suite also exercises existing privacy, connector path/cursor, MCP permission, cancellation, and provider-boundary behavior. Passing local tests do not constitute a full external penetration test or a proof that every secret format can be detected.

Graph labels are allow-by-screening metadata, not safe for arbitrary publication. The deterministic extractor may recognize a credential-like word as an entity; the graph path output now suppresses common key-shaped labels and URI/path patterns. Existing stored source text remains private unless a user explicitly requests content. Keep the daemon bound to loopback, restrict data-directory access, back up the SQLite database before upgrades, and avoid pasting private memory into a command argument. No automatic destructive repair is performed by doctor.
